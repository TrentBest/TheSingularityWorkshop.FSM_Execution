03 / Verified execution proof

Real FSM_API. Repeatable output.

This is the repository’s executable demonstration: a bounded C# scenario creates real FSM_API definitions, advances a fixed six-tick sequence, asserts cross-FSM behavior, and generates a TSV trace plus an SVG from observed state-entry events. CI runs it twice in separate processes and compares both outputs byte-for-byte.

Fox state path

Walking → Jumping → Walking → Fleeing → Mangled. The final Mangled transition is requested by the dog’s callback through the fox FSM handle.

Sheepdog state path

Sleeping → Awake → Chasing → Mangling. The deterministic inputs are scripted; this is not the original interactive SimpleDemos loop.

05 / Trust and authority

Evidence, execution, and permission are different things.

Execution can report what happened.

Accepted, Running, Succeeded, Failed, Cancelled, and TimedOut are distinct lifecycle outcomes. A handler that ignores cancellation cannot be forcibly stopped by a cooperative token.

Execution does not infer permission.

Model output, a green CI run, a valid evidence packet, or a CODE RED incident does not grant a repository capability. Human authorization remains in the host adapter.

Lifecycle scenarios are synthetic. The approval panel connects to the authenticated host API only when this page is served from the same origin as that host; the static GitHub Pages preview remains disconnected.
